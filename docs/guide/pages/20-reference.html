Good to know

  • One evaluation runs at a time. Finished results are saved as they complete. A run in progress lives in the running server, so if the server restarts, start that version again.
  • Nothing is run. No database is connected. Replies are read as SQL in the dialect you set with dialect= and checked for syntax, read-only, tables, columns and joins. Results are labelled “Static checks only”.
  • What is sent to a model. The judge gets each question, its expected SQL, the reply and what the checks found. Generating test cases sends the table, column and key names of your schema files to generator_model (the judge model by default). Choose models you are comfortable sending these to.
  • Schema files: .sql, .ddl and .txt with CREATE TABLE statements, up to 5 files of 10 MB. They are used only to write test cases and are not kept.
  • Judge versions. nl2sql_evalkit pins its LiteLLM dependency to a tested range, so installs stay on versions that have been checked.
  • The API. Everything the dashboard does is a call to /api/… on the same server; the interactive reference is at /api/docs.
