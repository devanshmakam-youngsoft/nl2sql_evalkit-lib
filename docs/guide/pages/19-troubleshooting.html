Start with the Problems during this run box on the version page: it says what went wrong in plain words, and Show technical details gives the error. The full log is the Download log button, or logs/runs/ in the data folder. Then look for your symptom here.

Every SQL score is 0, but nothing failed

A reply that has no SQL, does not parse in your dialect, or is not read-only is scored 0 without asking the judge. If every reply does this, the cause is usually the same: the function returns something the reader does not take as SQL, or the dialect is wrong.

Do: open one question and look at the Checks: they say which one failed and why. See the next entries for the usual causes.

“The assistant did not return any SQL”, but the SQL is there

A reply counts as SQL if it is inside a code fence, or if its first word is SELECT, WITH, INSERT, UPDATE, DELETE, DROP, CREATE, ALTER, TRUNCATE, MERGE, GRANT, REVOKE or EXPLAIN. A typo in the first word (SELEC) reads as an ordinary message, not as SQL. If your function returns a dictionary, the SQL must be under a known key.

Do: return just the query, or put it in a code fence; fix the typo; or add your key with answer_keys=["my_key"].

“The SQL does not parse as postgres” (or mysql, tsql, sqlite) on queries that are fine

The query is valid in another database. Every check reads the SQL in the dialect you set, and the default is postgres.

Do: set dialect= in serve() to the database your assistant writes for: "postgres", "mysql", "tsql" (SQL Server) or "sqlite". The same setting is used to read schema files when you generate test cases.

“The SQL is not read-only”

The reply holds more than one statement, something that changes data or the schema, or a risky function such as pg_sleep. It is scored 0 on purpose, and for a refuse case any SQL at all is wrong.

Do: make the assistant return a single SELECT. If the question was meant to be refused, mark its test case refuse and have the assistant decline in words.

The dashboard says “None yet” under Recommended version

No version reaches the minimum overall score (5 out of 10 by default), so nothing is recommended; the best so far is named. See Comparing versions.

Do: improve the assistant and run again, or check the test cases. If 5 is the wrong bar for you, set recommendation_min_quality.

A version says “Not compared”

It ran different test cases from the others (cases were edited, added or deleted), so there is nothing fair to compare. A case only counts as the same while its question and expected SQL are unchanged.

Do: run the same test cases on the versions you want to compare. The card shows the not-compared version’s own scores so a good one is not hidden.

Every question says “No answer: the assistant returned an error”

Your function raised an error. The run itself is fine: nl2sql_evalkit marks the question failed, records why, and carries on.

Do: open Problems during this run and Show technical details; the last lines name the error. Call your function by hand with one of the questions. Common causes: a key your own assistant needs (a model key, for example) is missing from .env, a file path that only works from another folder, something your app sets up at start-up was not set up before serve(), or the function needs a second argument that has no default.

“The question was answered, but the AI judge could not grade it”

The judge model did not answer. The usual reasons are shown in the message: a missing or wrong API key, a model name that does not exist, a rate limit, or no network.

Do: put the provider’s key in .env (GROQ_API_KEY, OPENAI_API_KEY…) or pass judge_api_key=; write the model as provider/model; for a rate limit, wait a minute or run fewer questions. Or use your own judge function, which needs no model. Questions that fail a basic check are still scored 0 without the judge.

“The AI could not write the findings for this run”

The findings come from the judge model, even when you use judge_fn.

Do: the same checks as above (key, model name, network). The scores and every answer are saved; only the written findings are missing.

The tables-and-columns score is blank

Nothing is expected for that question: its test case has no expected tables or columns, or it is a clarify or refuse case. It is left out, not scored 0.

Do: add expected_tables and expected_columns to the test case if you want them checked. If none of your cases has them, set schema_weight=0 so the overall score does not count them. See Writing test cases.

Tables or columns are reported missing, but the query looks right

The expected names are compared with the ones the query uses, ignoring case and quotes. A table.column expectation needs that same table, or its alias, in the query. A SELECT * is given the benefit of the doubt on columns.

Do: open the question: the checks list what was used and what was missing. Fix the expected names if they were wrong, for example a table that has since been renamed.

“Joins differ from the expected SQL” on a query that gives the same result

The joins check compares the pairs of columns the two queries join on. A query that reaches the same rows another way (a subquery instead of a join, or other keys) is reported as different, even if it is right.

Do: the judge’s SQL score still reflects whether the query is right. Leave the expected SQL out of the case if you only want tables and columns checked, or accept the difference.

The same question gets a different SQL score each run

The SQL score comes from an AI judge, and a model does not answer the same way every time. The checks (syntax, read-only, tables, columns, joins) never change.

Do: treat a difference of a point or so as noise. Set a lower judge_temperature if your model supports it, use a stronger judge_model, or write your own judge function for exact rules.

The step-time bar only shows “Not in a step”

No step ran during the questions, or recording was reduced.

Do: check that your pipeline calls nl2sql_evalkit.step(…) on the path the questions take; check record_mode is not "off".

Step times add up to more than the response time

One step sits inside another (the outer one includes the inner one’s time), or steps run in parallel.

Do: for nesting, make the steps follow each other instead of wrapping each other. Parallel steps are expected to overlap.

A step shows no inputs or output

Inputs and outputs are recorded only for decorated functions.

Do: use the decorator for that step, or record what you need with nl2sql_evalkit.note(). Arguments named like secrets show as [REDACTED] on purpose.

“Another evaluation is already running”

One evaluation runs at a time.

Do: wait for it, or press Stop on the version in progress; a stopped run keeps its partial results.

“Version … already exists” or “Version may only contain letters, digits…”

Version names are unique, and use letters, digits, ., _ or - (up to 20 characters).

Do: choose a new name, or tick the option to replace the existing version.

“No runnable test cases in the selection”

The groups you picked are empty, or their cases are all inactive.

Do: add cases to the group, or mark them active. The Execute dialog shows how many cases will run before you start.

A function with a parameter called context or user_id gets the wrong thing

Those names are on the lists nl2sql_evalkit uses to recognise history and session parameters.

Do: rename the parameter, or set history_params=[…] and session_params=[…] to your own names. See Connect your function.

The answer shows as a dictionary or object text instead of the answer

Your function returned a dictionary or object, and none of its keys is a known answer key.

Do: return a string, or add your key with answer_keys=["my_key"].

I cannot sign in, or I am signed out after a restart

The default account is admin / admin123 unless you set users=. Without a fixed secret= a new one is made on every start, which ends existing sessions.

Do: set users= and secret=, or require_login=False locally.

“Missing required column(s)” when importing

The file has no recognisable question column.

Do: use Test Cases → Import, which lets you pick which column is which; or add column_map= to serve().

Generating test cases: “no tables could be read”, or a file is skipped

The schema reader found no CREATE TABLE statements it could read in that file, or the file is the wrong kind or too large. Statements it cannot read are skipped and listed; a file with none readable fails. Only .sql, .ddl and .txt files are accepted (up to 5 files of 10 MB).

Do: check that the file really holds CREATE TABLE statements and that dialect= matches them (a SQL Server script read as postgres can fail on its brackets and GO lines). Split a huge dump, or remove its data.

Generated join questions are few, or the join check has little to compare

Joins are planned from foreign keys. Without declared keys the generator can only guess links from column names such as customer_id, and a schema with one table has none.

Do: add FOREIGN KEY clauses (or ALTER TABLE … ADD FOREIGN KEY) to the DDL you upload.

The dashboard looks old after an update, or a new option is not recognised

The environment still has the previous version of nl2sql_evalkit, or the browser kept the old page.

Do: reinstall with pip install --force-reinstall --no-deps git+https://github.com/devanshmakam-youngsoft/nl2sql_evalkit-lib.git, then refresh the page with Ctrl+F5.

“Address already in use”, or the page does not open

Another program is using the port, or the browser did not start.

Do: pick another one with port=8003 and open http://localhost:8003 yourself.

Where are the logs, and what should I send when asking for help?

Do: on the version page press Download log, or open logs/runs/ in your data folder (nl2sql_evalkit_data/ by default). For an error outside a run (a message with a reference number), search logs/server.log for that reference. Keys and passwords are already hidden.
