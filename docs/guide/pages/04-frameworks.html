LangGraph

Three placements work, and the example uses all three:

  • a node that calls a decorated function: the decorator records the call wherever it is made from;
  • a node with a with block inside it;
  • a decorator on the node itself, including nodes that take LangGraph's config parameter.
{{example:langgraph_agent.py}}

The version page then shows each step with its time. Parallel branches and async nodes (ainvoke) are recorded too; we ran this file and variants of it while writing this guide.

Good to know

A LangGraph node returns a state update such as {"sql": "SELECT …"}, and a decorated node records that dictionary as its output. The function you give to serve() is what returns the final SQL, so make it return the query itself, or a dictionary with a sql key.

Steps that run in parallel each report their own time, so together they can add up to more than the question's response time. That is expected.

LangChain

Steps work inside runnables, including the branches LangChain runs in parallel threads. The example is a chain whose stages are marked as steps.

Anything else that runs in your process

LlamaIndex, Haystack, hand-written loops, thread pools: nl2sql_evalkit remembers one thing, which question is being evaluated, and attaches every step to it. You do not need to pass anything around. Your pipeline's own code does not change when you add steps.
