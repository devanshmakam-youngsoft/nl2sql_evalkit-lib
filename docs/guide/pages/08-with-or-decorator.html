What each one records

Run the question “Total sales per region” through both and this is what the dashboard keeps:

Recorded for the stepwith blockDecorator
Step name and how long it tookyesyes
Inputs of the stepnot recordedevery argument, by name
Output of the stepwhat you assign to s.outputthe return value
Coversany block, even part of a functionthe whole function
Shown, not scored

A step’s inputs and output appear beside the question, which helps when you read a wrong query. The judge does not read them: it grades the SQL your function returns. The one thing you can hand to the judge is the schema the assistant looked at (next section).

Say which schema the assistant looked at

Most assistants pick the tables and columns that matter before they write the SQL. If yours does, say what it picked and the evaluator will check it, show it and tell the judge. Two ways, matching the two styles above:

  • with block: s.schema = ... inside with nl2sql_evalkit.step("schema_lookup") as s:. Give it text, a list of lines such as ["orders(id, amount)", "customers(id, name)"], or a dict such as {"orders": ["id", "amount"]}.
  • Decorator: @nl2sql_evalkit.step("schema_lookup", schema=True) takes the function’s return value as the schema.

This gives you three things on every question: the schema lookup score (0–10, the share of the expected tables and columns that were in what the assistant looked at), the schema itself in the question’s details with each expected table and column marked found or missing, and a likely cause from the judge when the SQL is wrong: the lookup missed something, the SQL went wrong with the schema it had, or both. If several steps declare a schema they are joined. If none does, nothing changes and the lookup score is not given. It is read, never run, and it is not part of the overall score that picks the recommended version.

Size

The schema is cut at 20,000 characters (serve(max_schema_chars=...)), and with record_detail="off" no content is kept, so no lookup score is given.

Which one should I use?

Use withFor parts of functionsYou can wrap just a few lines, and decide exactly what to attach to the question.
Use a decoratorWhen a function is one clear stageInputs and output show up in the step details with no extra code, which helps when chasing a wrong query.
Mix freelyOne pipeline can use bothA decorator on the model call, a with block on the table picker. They add up the same way.
