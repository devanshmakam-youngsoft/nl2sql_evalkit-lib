Chapter 6

The finance lead has a point: the assistant’s queries are right, but some read raw tables where a reporting view exists, and some add up amounts in different currencies. The default judge does not know that matters. Priya teaches it.

Level 1: another model

judge_model takes any LiteLLM model name, with its key in .env or judge_api_key=: "openai/gpt-4o-mini", "gemini/gemini-1.5-pro", "groq/llama-3.3-70b-versatile", "ollama/llama3". A fast model is a good choice while you iterate: every question that passes the basic checks makes one judge call (replies with no SQL, SQL that does not parse and SQL that is not read-only are scored 0 without one). Scores from a model can differ a little between runs.

Level 2: your own rubric

Keep the AI judge but tell it how your queries should be graded, for example which views to prefer or which mistakes count most. Pass it as judge_prompt=. Describe only the grading: nl2sql_evalkit adds the reply format (sql_marks, sql_comment, suggestion) itself, so a custom rubric cannot break the reply. summary_prompt does the same for the written findings.

Level 3: your own function

For exact checks, rules, or your own scoring service, replace the AI judge with a function: judge_fn(question, expected_sql, reply, checks). checks is a dictionary with what the checks found (syntax_ok, read_only, tables_used, tables_missing, columns_missing, star, joins_match, joins_missing, joins_extra…). Return a dictionary with sql_marks (0–10) and optionally sql_comment and suggestion. The tables-and-columns score is still worked out for you. A reply that has no SQL, does not parse or is not read-only is scored 0 before your function is called.

Scoring the written reply

If your assistant also writes a short reply for the user, give it a reply_style and that reply gets its own reply score from the judge model (judge_model, the same one). To score it with your own code instead, pass reply_judge_fn(question, reply_style, reply_text, sql) and return reply_marks (0–10) and optionally reply_comment and suggestion. It is called only for questions that have a reply style, and not when the assistant wrote no reply (that scores 0). judge_fn stays about the SQL.

Good to know

The written findings at the end of a run are produced by the judge model, even when you use judge_fn. Without a key for it the run still finishes, and the version says the findings could not be written.
