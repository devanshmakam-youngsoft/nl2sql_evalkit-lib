Chapter 1

Priya decides not to argue about version 2 any more. The plan: write down ten questions colleagues really ask, run them through Sidekick, and look at the scores.

  1. Install 
    pip install git+https://github.com/devanshmakam-youngsoft/nl2sql_evalkit-lib.git

    On Windows, run this from Git Bash if git is not on your PowerShell path.

  2. Give the judge a model

    The judge is an AI model that grades the SQL. Put its key in a .env file next to your script and nl2sql_evalkit reads it. The default judge is a Groq model, so:

    # .env
GROQ_API_KEY=your-key-here

    Any LiteLLM provider works, and you can skip the AI judge entirely.

  3. Serve your function

    Create eval_entry.py next to your pipeline. Any function that turns a question into SQL works. Say which SQL dialect your database speaks with dialect: "postgres" (the default), "mysql", "tsql" for SQL Server, or "sqlite".

    import nl2sql_evalkit
from my_app import question_to_sql          # your existing pipeline

nl2sql_evalkit.serve(question_to_sql, port=8002, require_login=False, dialect="postgres")
    python eval_entry.py

    The dashboard opens at http://localhost:8002. Without require_login=False the sign-in is admin / admin123.

  4. Add test cases

    Open Test Cases and press + New test case. Write a question and the SQL you would expect. Adding the expected tables and columns makes the checks sharper. Ten is plenty to start. Later you can import a spreadsheet or have nl2sql_evalkit write cases from your own .sql or .ddl schema file.

  5. Run it

    Press Execute session, name the version 1, choose your test cases and start. A progress bar follows each question.

  6. Read the result

    Open the version. You get an average SQL score and tables-and-columns score, the response time, a table of where answers fail (which checks the SQL did not pass), plain-language findings, and every question with the SQL it got, the judge's reason and a suggestion.

What good looks like

Scores are out of 10. As a rule of thumb: 8 and up is strong, 5 to 7 is fair, under 5 means the SQL is mostly wrong or missing. The numbers matter less than the change between versions, which is what the rest of this guide is about.

If every score is 0.0

Do not panic. A reply that has no SQL, does not parse in your dialect, or is not a read-only SELECT scores 0 straight away, without asking the judge. So it almost always means nl2sql_evalkit is not seeing your SQL: the function returns something else, the SQL sits under a key it does not know, or dialect does not match what your assistant writes. Open one question and read the reply it recorded. Troubleshooting has the details.
